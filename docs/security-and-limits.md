# Безпека, генерація, зберігання та ротація ключів

## 1. Симетричні ключі

`secrets.token_bytes()` створює AES-128/192/256 майстер-ключ (CSPRNG). На диску зберігається **лише** зашифрований ключ: `Scrypt(n=32768,r=8,p=1,salt=16 bytes)` породжує ключ для AES-GCM; `nonce=12 bytes` випадковий. Файл зазвичай має права `0600` на POSIX. Пароль не передається як CLI-аргумент, береться з `CRYPTO_PASSWORD` або вводиться без відображення. Дійсні ключі та паролі **не комітити**.

При кожному шифруванні даних новий **16-байтний salt** відділяє ключ файла через HKDF-SHA256. GCM використовує новий 12-байтний nonce. CBC використовує випадковий 16-байтний IV; ключі AES і HMAC виводяться незалежними сегментами HKDF. HMAC-SHA256 перевіряється **до** CBC-дешифрування (Encrypt-then-MAC).

## 2. Ротація

`python cli.py sym rotate --label default --bits 256` створює **новий** майстер-ключ і 128-бітний ID, оновлює active ID. Раніше зашифровані файли продовжують розшифровуватися, оскільки старий ID знаходиться в їхньому заголовку, а попередній ключ зберігається в encrypted key store. Для демонстрації рекомендується ротація щоквартально, негайно після компрометації або за локальною політикою; терміни є **навчальною політикою проєкту**, не універсальним нормативом. При компрометації потрібне також повторне шифрування на новому ключі: сама ротація не захищає старі ciphertext.

## 3. RSA

RSA `2048/3072/4096` генерується бібліотекою `cryptography` із показником `65537`. Приватний ключ експортується в **зашифрований PKCS#8 PEM** через BestAvailableEncryption(password); публічний — SubjectPublicKeyInfo PEM. OAEP-SHA256 призначений тільки для малих повідомлень; PSS-SHA256 забезпечує цифровий підпис та перевірку. Гібридне шифрування працює незалежним випадковим AES-256 ключем на кожен файл.

## 4. Виняткові ситуації

Відхиляються пошкоджені JSON-контейнери, хибний пароль, неправильний PEM, невірний MAC/GCM tag, неправильний отримувач, неприпустимі розміри ключів і надто великі файли. Вихідний файл створюється **лише після успішної автентифікації**. Лог фіксує події без ключів, паролів, plaintext і повних шляхів.

## 5. Обмеження

Демонстраційна програма обробляє файл у пам'яті, розмір обмежено 64 MiB. Код не проходив сертифікації та не замінює HSM/KMS; в операційній пам'яті Python немає гарантій zeroization. Логи теж потребують захисту. Дозволи POSIX застосовуються на Kali; Windows використовує власні ACL. Оцінка продуктивності включає накладні витрати Python, HKDF та контейнерів, тому не є прямим мікробенчмарком AES block-cipher throughput.
